<damit-viewer> — Web Component embed

Same widget, different API: register the bundle once and use <damit-viewer> as a plain HTML tag. Below are two forms — by explicit URL (works today, no CORS to negotiate) and by DAMIT model id (needs an Access-Control-Allow-Origin header on the damit.cuni.cz responses, or a same-origin proxy).

Form 1 — explicit URLs (recommended for DAMIT pages)

The page that already serves the model file can pass its URL directly. This is the lowest-friction integration: same origin, no CORS, no URL-pattern assumptions. Use it inside a server-rendered DAMIT page where the file paths are templated in. 

<script src="./damit-viewer.umd.js"></script>
<damit-viewer
  shape-url="./sample-data/hermione/shape_damit_155.txt"
  lc-url="./sample-data/hermione/herm.lc"
  name="(121) Hermione"
  period-hours="5.55128"
  pole-lambda="293"
  pole-beta="-34"
  jd0="2443032.5"
  refit-pole
  initial-lc-index="9"
  initial-view="earth">
</damit-viewer>

Form 2 — by DAMIT model id

If you'd rather not template URLs, point the element at a DAMIT instance by model id. The element will resolve https://damit.cuni.cz/asteroid_models/files/obj/<id>.obj for the shape and https://damit.cuni.cz/asteroid_models/lc/<id>.txt for the photometry. This currently requires DAMIT to set Access-Control-Allow-Origin: * on those endpoints — without that header, the browser blocks the cross-origin fetch. Until then, you can point damit-base at your own proxy. 

// In DAMIT, the shape file is keyed by model id; light curves are keyed by
// asteroid id (one asteroid can have multiple shape models).
<script src="./damit-viewer.umd.js"></script>
<damit-viewer
  model-id="103"          // resolves /generated_files/open/AsteroidModel/103/shape.obj
  asteroid-id="102"       // resolves /light_curves/exportAllForAsteroid/102/json
  name="(3) Juno"
  period-hours="7.21"
  refit-pole>
</damit-viewer>

// or with a CORS proxy you control:
<damit-viewer
  model-id="103" asteroid-id="102"
  damit-base="https://your-proxy.example/damit"
  ...></damit-viewer>

Attribute reference

// Data source — choose one form
shape-url         // URL of a shape file (Wavefront OBJ or DAMIT shape.txt; auto-detected)
lc-url            // URL of a light-curve file (JSON or DAMIT lc.txt; auto-detected)
model-id          // DAMIT model id; combines with damit-base for the shape URL
asteroid-id       // DAMIT asteroid id; combines with damit-base for the LC URL
damit-base        // default https://damit.cuni.cz (override with a CORS proxy)

// Published spin parameters (auto-fit if refit-pole is set)
period-hours      // required when refit-pole is set
pole-lambda       // degrees, ecliptic J2000 (defaults 0)
pole-beta         // degrees (defaults 0)
jd0               // epoch of zero rotation phase (defaults to first LC obs)

// Behaviour
refit-pole        // presence-only attribute; runs the optimiser at load
lambert-c         // scattering coefficient (default 0.10)
name              // display name in the widget header
initial-lc-index  // integer; default 0
initial-view      // 'free' | 'earth'; default 'free'

Same widget you've already seen — the Custom Element wrapper just translates attributes into the imperative DAMITViewer.mount() call and handles re-loading when attributes change.
