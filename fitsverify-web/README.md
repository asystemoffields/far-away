# fitsverify-wasm

**NASA/HEASARC's `fitsverify` compiled to WebAssembly — validate FITS files for
standards conformance entirely in the browser or Node, with no upload and no
install.**

FITS is the standard data format in astronomy. `fitsverify` (HEASARC, in use
since 1994) is the canonical tool for checking a file against the
[FITS Standard](https://fits.gsfc.nasa.gov/fits_standard.html). Until now the
only ways to run it were to compile the C tool against CFITSIO yourself, or to
upload your file to a [CGI form on a NASA server](https://heasarc.gsfc.nasa.gov/cgi-bin/Tools/fitsverifier/fitsverifier.pl).
This package runs the *same* checks client-side: your data never leaves the page.

It builds on Demitri Muna's [`libfitsverify`](https://github.com/demitri/fitsverify) —
a reentrant, embeddable refactor of the original tool that preserves all ~60
validation checks — plus [CFITSIO](https://github.com/HEASARC/cfitsio),
compiled to a single ~210 KB-gzip WASM module.

## Use it

```ts
import { verifyFits } from 'fitsverify-wasm';

const bytes = new Uint8Array(await file.arrayBuffer());
const report = await verifyFits(bytes, { fixHints: true });

if (report.ok) {
  console.log(`Conformant — ${report.numHdus} HDUs, ${report.numWarnings} warnings`);
} else {
  for (const m of report.messages) {
    console.log(`${m.severity} [HDU ${m.hdu}] ${m.text}`);
    if (m.fixHint) console.log(`  → ${m.fixHint}`);
  }
}
```

`verifyFits(input, options?)` accepts a `Uint8Array` or `ArrayBuffer` and returns:

```ts
interface FitsReport {
  ok: boolean;          // conformant = zero errors and not aborted
  numErrors: number;
  numWarnings: number;
  numHdus: number;      // Header-Data Units processed
  aborted: boolean;     // verification stopped early (fatal structural error)
  messages: FitsMessage[];  // warnings + errors, in report order
  version: string;
}
interface FitsMessage {
  severity: 'info' | 'warning' | 'error' | 'severe';
  code: number;         // libfitsverify error code
  hdu: number;          // 1-based HDU, or 0 for file-level
  text: string;
  fixHint?: string;     // when options.fixHints
  explain?: string;     // when options.explain
}
```

Options: `{ fixHints?, explain?, testChecksum?, errorsOnly?, label? }`.

## Demo

`web/index.html` is a zero-build, drag-and-drop validator page (the file is
validated locally; nothing is uploaded).

## Correctness

The WASM build is **byte-for-byte identical to the native `libfitsverify`** on a
corpus of valid and deliberately-malformed FITS files (generated by the
upstream `gen_test_fits.c`) — matching error/warning counts *and* every message
code. See `test/corpus.test.ts` and `test/golden.json`; run `npm test`.

The corpus and golden values were locked in by differential testing against the
native library; the committed test then guards the WASM build, the C shim, and
the TypeScript wrapper against regression.

## Building the WASM module

`dist/fitsverify.{mjs,wasm}` are committed so the package and demo work without a
toolchain. To rebuild:

```bash
# Requires Emscripten on PATH (source emsdk_env.sh). Tested with emcc 5.0.7.
npm run build:wasm
```

`build.sh` auto-vendors the pinned upstream sources (`HEASARC/cfitsio`,
`demitri/fitsverify`) into `vendor/` (gitignored), patches CFITSIO's
endianness detection for wasm32 (it has no wasm branch and otherwise byte-swaps
backwards), builds CFITSIO against Emscripten's zlib port, then links
`libfitsverify` + a small C shim (`src/fv_wasm.c`) into the module.
